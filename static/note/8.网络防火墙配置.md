# 网络防火墙配置（iptables）


## 一、概述

本防火墙基于 **iptables**（Linux 内核 Netfilter 框架的标准工具）实现，用于对网络**入方向（INPUT）**流量进行访问控制（ACL，Access Control List）。

基本思路：

- 默认策略为 **DROP**（丢弃），仅放行明确允许的流量（最小权限原则）。
- 仅在 `INPUT` 链上进行入方向 ACL 过滤。
- 规则区分为 **TCP** 和 **UDP** 两大类，分别以 `--protocol tcp` 和 `--protocol udp` 匹配。
- 对流量进行状态跟踪（`state`），放行已建立连接及回程流量。


## 二、架构与拓扑

```
                  Internet / 外部网络
                        │
    ┌───────────────────▼───────────────────┐
    │           防火墙 (iptables)             │
    │  INPUT 链（入站 ACL）                    │
    │   TCP 规则组 ─┐                        │
    │   UDP 规则组 ─┘                        │
    └───────────────────┬───────────────────┘
                        │
              ┌─────────┴─────────┐
              │   内部服务器 / 业务  │
              └───────────────────┘
```


## 三、数据包流量流程

1. 数据包进入 → 防火墙应用层 → Netfilter。
2. 经过 `PREROUTING` → 路由判断 → 目的地址为本地 → 进入 `INPUT` 链。
3. 在 `INPUT` 链中按规则顺序从上往下匹配：
   - 命中 **允许** 规则 → 通过（`ACCEPT`）。
   - 命中 **拒绝** 规则 → 丢弃/拒绝（`DROP` / `REJECT`）。
   - 全部不匹配 → 应用默认策略（`DROP`）。

```
Packet → PREROUTING → Routing → INPUT (ACL: TCP/UDP) → 本地进程
                                   │
                            ┌──────┴──────┐
                            │  匹配允许    │ → ACCEPT
                            │  匹配拒绝    │ → DROP (UDP) / REJECT (TCP)
                            │  无匹配      │ → 默认策略 DROP
                            └─────────────┘
```


## 四、规则设计


### 1. 默认策略

```bash
# 清空现有规则
iptables -F
iptables -X

# 设置默认策略为拒绝入站
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT
```

> **说明**：默认丢弃所有入站流量，仅通过显式规则放行所需服务，确保安全。


### 2. 回环接口与已建立连接（放行）

```bash
# 允许本地回环
iptables -A INPUT -i lo -j ACCEPT

# 放行已建立及回传连接（TCP/UDP 通用，含 ICMP 回显应答）
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
```

> 状态跟踪同时覆盖 TCP 和 UDP。


### 3. TCP 类入站 ACL

按服务端口逐条放行（示例端口可自行增删）：

```bash
# SSH (22)
iptables -A INPUT -p tcp -m state --state NEW -m tcp --dport 22 -j ACCEPT

# HTTPS (443)
iptables -A INPUT -p tcp -m state --state NEW -m tcp --dport 443 -j ACCEPT

# HTTP (80)
iptables -A INPUT -p tcp -m state --state NEW -m tcp --dport 80 -j ACCEPT
```

**更严格的做法**：限定来源地址（白名单）：

```bash
# 仅允许内网/特定 IP 访问 SSH
iptables -A INPUT -p tcp -s 192.168.1.0/24 --dport 22 -j ACCEPT
```


### 4. UDP 类入站 ACL

```bash
# DNS (53)
iptables -A INPUT -p udp -m state --state NEW -m udp --dport 53 -j ACCEPT

# NTP (123)
iptables -A INPUT -p udp -m state --state NEW -m udp --dport 123 -j ACCEPT

# 常见 SNMP (161)
iptables -A INPUT -p udp -m state --state NEW -m udp --dport 161 -j ACCEPT
```

> **⚠️ 关于 UDP 与 `--state NEW` 的特殊说明**
>
> 由于 **UDP 是无连接协议**，`conntrack` 对 UDP 的 NEW / ESTABLISHED 状态跟踪**不可靠**：
> - UDP 没有 TCP 那样的三次握手，"连接" 仅由 conntrack 临时维护的软超时近似（通常几秒到几十秒无后续报文即被回收）。
> - 因此 `--state NEW` 这类"仅针对新建流量放行"的匹配，对 UDP 无法稳定生效（可能被绕过，行为不可预期），效果往往退化为"照单全收"。
>
> **推荐做法**：UDP 入站 ACL **去掉 `-m state --state NEW`**，直接按端口匹配即可：
>
> ```bash
> # DNS (53) —— 正确写法
> iptables -A INPUT -p udp --dport 53 -j ACCEPT
> ```


### 5. 拒绝策略选择

- **TCP 类**：建议使用 `REJECT` 返回明确拒绝信息，便于排错。若希望隐蔽服务可用端口，也可使用 `DROP`。
- **UDP 类**：无握手过程，建议使用 `DROP`，静默丢弃，避免暴露服务存在性。

```bash
# TCP 显式拒绝示例
iptables -A INPUT -p tcp --dport 23 -j REJECT --reject-with tcp-reset

# UDP 显式拒绝示例
iptables -A INPUT -p udp --dport 161 -j DROP
```


## 五、完整配置脚本（实例）

```bash
#!/bin/bash
# 网络防火墙入站 ACL 配置脚本
# 实测适用于 CentOS / Ubuntu，判断是否以 root 运行
if [ "$EUID" -ne 0 ]; then
  echo "请以 root 身份运行"
  exit 1
fi

echo "=== 1. 清空规则 ==="
iptables -F
iptables -X

echo "=== 2. 设置默认策略 ==="
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

echo "=== 3. 放行回环与已建立连接 ==="
iptables -A INPUT -i lo -j ACCEPT
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

echo "=== 4. TCP 入站 ACL ==="
iptables -A INPUT -p tcp -m state --state NEW -m tcp --dport 22  -j ACCEPT  # SSH
iptables -A INPUT -p tcp -m state --state NEW -m tcp --dport 80  -j ACCEPT  # HTTP
iptables -A INPUT -p tcp -m state --state NEW -m tcp --dport 443 -j ACCEPT  # HTTPS
iptables -A INPUT -p tcp -s 192.168.1.0/24 -m tcp --dport 3306 -j ACCEPT     # MySQL 白名单

echo "=== 5. UDP 入站 ACL ==="
# 注意：UDP 为无连接协议，--state NEW 对其不可靠，直接按端口匹配
iptables -A INPUT -p udp --dport 53   -j ACCEPT  # DNS
iptables -A INPUT -p udp --dport 123  -j ACCEPT  # NTP

echo "=== 6. 查看结果 ==="
iptables -L INPUT -n -v --line-numbers

echo "=== 7. 保存规则（各发行版略有差异） ==="
# CentOS / RHEL
service iptables save
# 或 Ubuntu（netfilter-persistent）
# 或 Ubuntu（netfilter-persistent）
# netfilter-persistent save
```


## 五、操作流程

实际运维中通常**直接编辑防火墙规则文件 `/etc/sysconfig/iptables`**（CentOS/RHEL），并在应用前**预校验**，避免因语法错误导致防火墙失效。

```bash
# 1. 编辑规则文件（CentOS/RHEL）
sudo vi /etc/sysconfig/iptables

# 2. 预校验：语法检查，只测试不生效，出错会提示而不改动现网
sudo iptables-restore --test < /etc/sysconfig/iptables

# 3. 重启防火墙使配置生效
sudo service iptables restart

# 4. 验证结果
sudo iptables -L -n -v   # 查看各链是否仍有规则以及命中计数
sudo iptables -S          # 完整规则列表（覆盖 filter、NAT、RAW、MANGLE 等所有表）
```

> **说明**
>
> - `iptables-restore --test`：对配置文件做**语法校验**，合法才继续，安全可靠。若文件有语法错误会直接提示，此时不要执行 `restart`。
> - `iptables -L -n -v`：以数字 IP、Verbose 模式查看链规则与已匹配包/字节计数，用于确认 ACL 是否加载并命中。
> - `iptables -S`：输出**完整规则**（含 `RAW`、`NAT`、`MANGLE` 表），更适合全面核对配置。


## 七、说明与备注

| 项目 | 说明 |
| ---- | ---- |
| INPUT 链 | 入站流量过滤链，防火墙 ACL 主体 |
| 默认策略 | DROP，仅放行显式规则 |
| 状态匹配 | `--state NEW` 仅针对新建连接放行 |
| TCP / UDP 区别 | TCP 用 `reject-with` 返回拒绝信息，UDP 用 `DROP` 静默丢弃 |
| 来源限制 | 使用 `-s <网络>` 白名单强化 ACL |

## 九、查看与测试

```bash
# 查看 INPUT 链规则
iptables -L INPUT -n -v --line-numbers

# 查看当前匹配计数（验证 ACL 是否生效）
iptables -L INPUT -n -v -x | grep -v "^Chain"

# 临时测试放行后删除某条规则
iptables -D INPUT <规则编号>    # 或 iptables -D INPUT 规则参数
```


## 十、安全提醒

- **先确认远程管理端口（如 22）已放行，再执行默认策略 DROP**，避免被锁在系统外。
- 生产环境建议配合防火墙 `save` 持久化，防止重启失效。
- 规则顺序敏感（从上到下匹配），将最严格的规则放在最前面。
- 建议同时开启 ssh 白名单等多层防护策略。
